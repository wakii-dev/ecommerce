## Spec slice (chỉ phần SF-2 chịu trách nhiệm)

1. **Session-sync module** (`packages/auth/src/session-sync.ts`): BroadcastChannel primary (channel name vd `ecommerce.auth`) + `storage` event fallback (localStorage sentinel với version/timestamp — message KHÔNG mang token). **SSR-guard**: lazy client init — KHÔNG BroadcastChannel top-level (renderToStaticMarkup phải sạch; module không crash ở Node).
2. **AuthStore hooks**: broadcast CHỈ trên state TRANSITION auth↔unauth — cắm tại `setToken` (AuthStore.ts:80-84) và `logout` (:199-204) qua 1 wrapper nhỏ; receiver KHÔNG re-broadcast trừ khi chính nó transition (chặn BC loop N-tab: nhận logout-broadcast → refresh → 401 → logout → broadcast lại).
3. **Cross-tab refresh coordination (P0 — race one-time rotate)**: refresh cookie là ONE-TIME rotate (auth-cookie.spec:41-72); refresh() fail → logout() ngay (AuthStore.ts:146-157); single-flight hiện tại per-tab (AuthStore.ts:69-70,163-166) — N tab refresh đồng thời với cùng cookie → 1 thắng, N-1 nhận 401 → spurious logout. Phải: (a) serialize refresh đa tab — `navigator.locks` (`navigator.locks.request('ecommerce.auth-refresh', ...)`) primary, BC handshake `refresh-start/refresh-done` fallback; (b) **401-refresh → retry ĐÚNG 1 lần sau backoff ngắn (~300-500ms) TRƯỚC khi logout** (cookie mới đã host-wide sau tab thắng); (c) giữ single-flight per-tab như cũ bên trong lock.
4. **Receiver flow**: nhận `{type:'auth-changed'}` → gọi `authStore.refresh()` (cookie roundtrip — an toàn XSS, không áp token từ message) → state cập nhật → notify → UI đổi. ≤1 POST refresh per tab per event (coordination đảm bảo).
5. **configureAuth auto-start**: listener khởi động tự động trong `configureAuth` (api.ts:36-43 config flow) — app KHÔNG phải gọi tay; vẫn idempotent (multiple configureAuth không nhân bản listener).
6. **Redirect 127.0.0.1 → localhost**:
   - Next: `apps/storefront-web/middleware.ts` — host `127.0.0.1` → 301/308 `localhost` cùng path+query; **matcher loại trừ `/_next` + static assets** (redirect trên asset = refetch sai host); không loop (localhost ≠ 127.0.0.1 trigger).
   - Vite: plugin middleware trong `packages/config/vite-preset.mjs` (configureServer — anchor: CHỈ thêm plugin, KHÔNG đụng SHARED_SINGLETONS vùng SF-1).
7. **Guest cart token consistency check (binary)**: assert localStorage key `ecommerce.guest_cart_token` được read/write từ cả 2 app trên CÙNG 1 origin (jsdom test simulated 2 app context cùng key) — token stale từ origin dev cũ là dev-only self-heal (merge 400/404 → forget im lặng, cartApi.ts:177-192), KHÔNG phải acceptance.
8. **Unit tests**: jsdom BroadcastChannel mock + storage fallback + rotate-race case (2 tab refresh đồng thời — mock fetch 401-then-OK) + transition-only broadcast + SSR render sạch. Có trong `packages/auth/src/__tests__/`.
9. **e2e auth-cookie extension (multi-tab)**: mở rộng `frontend/e2e/tests/auth-cookie.spec.ts` (HTTP-level Set-Cookie qua proxy :21) — scenario sync dùng **2 PAGES (tabs) TRONG CÙNG 1 Playwright context** (P1: 2 contexts = cookie jar + storage partition RIÊNG → refresh cookie httpOnly + BroadcastChannel/storage KHÔNG xuyên context → demo fail 100% như viết sai; pageA.newPage() share cookie+BC): login page A → page B thấy session; logout A → B out. Env TỰ THÂN (E2E_* vars hiện có) — KHÔNG đợi SF-3.
10. **ADR session-sync contract**: `docs/adr/` — channel name, message shape, transition-only rule, coordination mechanism, retry-once rule, SSR-guard; ADR roadmap migration (b) là của SF-5 (không phải bạn).
