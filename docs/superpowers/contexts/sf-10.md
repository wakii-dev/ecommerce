## Spec slice (chỉ phần SF-10 chịu trách nhiệm)

1. **Live wiring checkout**: mfe-checkout tắt `VITE_ORDERING_STUB` (default OFF) → gọi ordering thật: `POST /orders` → `clientSecret` thật → Stripe.js confirm → confirmation page **poll order status** tới CONFIRMED (hoặc hiện lỗi FAILED kèm lý do). **Thêm consumer `order.confirmed` vào cart-service** (file-slice: xóa cart items theo user sau khi mua — §3.2).
2. **notification-service** (service mới từ template, port 8087): consumers `order.confirmed` (email xác nhận tiếng Việt: items + tổng — Mailpit), `order.cancelled` (email hủy), `review.moderated` (email kết quả duyệt — nếu payload có email; thiếu → skip log). SMTP host Mailpit compose (SF-1). Send-log table đơn giản. Template inline theo direction (không cần lib nặng).
2b. **log-service** (service mới từ template, port 8088, **D14 — Mongo**): consumer fan-in — queue bind topic exchange `#` (TẤT CẢ domain events) → ghi document vào Mongo collection `event_log`: `{eventId, eventType, routingKey, occurredAt, correlationId, payload, receivedAt}` + index `{eventType, occurredAt}`. spring-boot-starter-data-mongodb, `MONGO_URI` từ env (container từ SF-1). KHÔNG REST write API; đọc log qua mongo-express :8089. Idempotent consume (eventId dedupe). Đây là audit trail demo: action trên UI → document xuất hiện.
3. **Gateway full route table**: rà đủ 7 services + public-paths đúng + **route split D16** (`/`, `/c/*`, `/p/*`, `/search`, `/coupons`, sitemap/robots → storefront-web:3000; `/cart|/checkout|/account|/admin` → shell); CORS prod; profile `full`: serve static FE (shell + 3 remotes) + **storefront-web `next build` standalone (container riêng)**.
4. **`make dev` fullstack**: 1 target = compose infra + 7 services dev mode + storefront-web (`next dev`) + shell + 3 vite apps (turbo dev --parallel, env wiring đúng `REMOTE_*_URL` + `GATEWAY_URL`, ports table). `make full`: compose profile `full` — Dockerfiles mọi service + FE → stack 100% containerized.
5. **Deterministic seed** (script idempotent, profile seed): admin `admin@demo.vn` / password từ env; user demo `user@demo.vn`; coupon `WELCOME10` (10%, limit 100, hết hạn +30 ngày) + `GIAM50K` (fixed 50.000₫); products tên dễ search ("Tai nghe Bluetooth XYZ", "Áo thun nam..." — pin chính xác trong seed file); flash sale +2 ngày; 1-2 đơn hàng CONFIRMED trước đó cho dashboard có data (tạo QUA API thật hoặc seed DB — agent quyết, ghi rõ cách); 1 review APPROVED sẵn.
6. **Playwright E2E** (`frontend/e2e/`, chạy với stack dev + stripe-cli + keys .env):
   - `golden-path.spec.ts` (§5.2): browse home → search → PDP → register user mới → add to cart → coupon WELCOME10 → checkout → Stripe 4242 → confirmation CONFIRMED → Mailpit API có email xác nhận → login admin → thấy đơn CONFIRMED.
   - `admin-crud.spec.ts` (§5.3): admin tạo product publish → storefront PLP/PDP thấy.
   - `review-flow.spec.ts` (§5.6): user (đã có đơn CONFIRMED từ golden path hoặc seed eligibility) viết review → admin approve (API) → PDP hiện review + badge "Mua đã xác nhận".
   - `saga-fail.spec.ts` (§5.7): checkout card 4000...0002 → order FAILED + availability API hồi phục (reservation released) + coupon dùng lại được.
   - `rbac.spec.ts` (§5.5): curl không token → 401; customer token → `/api/admin/**` 403.
   - `standalone.spec.ts` hoặc script (§5.4): từng service health OK khi chạy đơn lẻ với compose infra.
7. **Demo README + script**: README root (kiến trúc sơ đồ ngắn, quickstart, accounts, thẻ test, kịch bản demo 5 phút theo section), `docs/demo-script.md`.
8. **ADR finalize** (`docs/adr/`): saga orchestration + outbox, contracts freeze policy, auth RS256 flow, service boundaries (reviews/wishlist trong catalog, coupons trong ordering — D9 + extract path).
9. **Perf sanity**: catalog cache hit (log/2 lần gọi), không N+1 rõ rệt ở PLP; **security sanity**: secrets chỉ qua env (grep không có key trong code), validation tại boundaries (spot check register/coupon).
